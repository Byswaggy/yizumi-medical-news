# 医塑情报网站优化需求规格说明（FS）

**项目名称：** 医塑情报——医疗注塑行业资讯聚合与智能筛选平台  
**文档版本：** V1.0  
**日期：** 2026-10-14  
**目标系统：** https://yzmimmmedicalindustry.coze.site/  
**适用对象：** 开发 Agent、前端/全栈开发、测试人员  
**需求性质：** 在现有网站基础上迭代，不推倒重建

## 0. 开发执行摘要

本项目只优化行业资讯的**采集结果展示、硬筛选、评分解释、搜索分类、阅读体验、数据一致性和资讯质量控制**。网站定位是医疗注塑行业资讯聚合与智能筛选平台，不是 CRM，也不是销售跟进系统。

开发必须遵守以下约束：

1. **先检查现有项目再修改。** 盘点现有页面路由、组件、数据模型、采集流程、筛选规则、评分计算和 AI 分析字段；尽量复用当前实现，不得无理由重建项目或替换技术栈。
2. **保留当前业务规则。** 硬筛选仍为：新闻发布时间在最近 360 天内；至少命中一个产品词；并且至少命中一个工艺词或事件信号词。三项逻辑为 `时间 AND 产品词 AND (工艺词 OR 事件词)`。
3. **保留现有六维加权评分。** 注塑直接相关性 25%、投资事件强度 20%、产品匹配度 20%、采购时效性 15%、客户价值 10%、信息完整度 10%。六维评分与详情页七维 AI 分析不得混为一套规则。
4. **保留未入选资讯。** 未通过精选规则的文章不能被删除；应继续出现在「全部资讯」中，并显示可理解的未入选原因。
5. **不开发销售后续管理。** 本期不建设 CRM、客户跟进任务、责任人分配、销售阶段、客户联络记录或销售漏斗。
6. **不伪造数据。** 计数、评分、更新时间、信源状态和日期必须来自真实数据或清晰的空状态，不得使用写死的演示数字作为正式数据。
7. **先保证数据一致性，再做 UI。** 发布时间、采集时间、AI 分析时间、进入精选时间必须各自独立，不能互相替代。

## 1. 项目背景与目标

### 1.1 产品定位

面向医疗注塑及相关医疗制造领域的行业资讯平台，聚合行业媒体、企业公告和技术动态，通过规则筛选和 AI 分析降低用户阅读成本，帮助用户持续了解：

- 医疗器械、医用耗材、医疗包装及医疗制造相关动态；
- 注塑工艺、精密注塑、微注塑、液态硅胶、模具、医用塑料材料等技术变化；
- 企业投资、扩产、并购、新工厂、新产品、法规及市场变化；
- 每篇资讯的原始来源、事实摘要、相关度判断、评分及 AI 分析依据。

### 1.2 本次优化目标

- 用户能快速找到最新或高价值的行业资讯。
- 用户能区分「最新资讯」「精选资讯」和「近 48 小时热点」。
- 新闻时间、统计口径、评分展示和筛选状态一致、可解释。
- 用户能在列表页初步判断一篇文章是否值得阅读。
- 用户能在详情页区分原文事实、AI 推断和未知信息。
- 采集源异常、发布时间缺失、重复内容及解析失败等状态可见、可排查。
- 网站在桌面和移动端均可使用，优先保障桌面阅读效率。

### 1.3 成功指标

上线后至少能够统计以下指标，首期不要求建设复杂 BI：

1. **精选命中准确性**：抽样复核精选文章中，符合硬筛选规则且医疗注塑相关性判断合理的比例。
2. **资讯新鲜度**：最新文章的原始发布时间与当前时间的差值；分别统计采集延迟与分析延迟。
3. **重复事件率**：同一事件重复占用精选列表的比例。
4. **事实一致性**：AI 摘要/分析中无原文支持的事实性表述占比。
5. **采集健康度**：按信源统计最近成功时间、运行结果和解析成功率。

具体目标值应先根据现有数据建立基线，再设定，不得无依据地宣称已达标。

## 2. 本期范围与非目标

### 2.1 本期范围

- 首页信息层级与资讯列表优化；
- 全部资讯的搜索、分类筛选、排序及未入选原因显示；
- 热点榜时间窗口和统计口径一致化；
- 新闻详情页的结构、评分依据和来源信息优化；
- 关于页面的规则说明结构化；
- 时间字段、评分字段和信源运行状态的统一；
- 资讯去重/同事件归并的设计与基础能力（优先 P1）；
- 注塑工艺语义标识、评分置信度和事实/推断区分（按优先级分阶段实施）；
- 响应式布局和基本交互验收。

### 2.2 明确不做

- CRM、客户管理和联系人管理；
- 销售跟进任务、责任人分配、销售阶段、报价管理；
- 自动联系客户、发送销售邮件或销售线索分派；
- 以本期优化为由替换整个采集框架或迁移技术栈；
- 在没有数据依据的情况下增加实时新闻数量、虚构信源状态或生成假评分；
- 未经核对直接更改 360 天时间窗、关键词规则、六维权重或现有分数阈值。

## 3. 现有业务规则（开发基准）

### 3.1 硬筛选规则

一篇资讯进入精选需同时满足：

```text
精选资格 = 时间条件 AND 产品词条件 AND (工艺词条件 OR 事件信号词条件)
```

条件定义：

- **时间条件**：原始新闻发布时间位于最近 360 天内。
- **产品词条件**：至少命中一个产品词或已配置的同义词。
- **工艺/事件条件**：至少命中一个工艺词，或者一个事件信号词。
- 三项条件为 AND 关系；括号中的工艺词与事件词为 OR 关系。
- 未通过条件的资讯保留在「全部资讯」，并记录一个或多个原因。
- 不得用 `fetched_at`（抓取时间）替代 `published_at`（新闻发布时间）判断 360 天窗口。
- 新闻发布时间缺失或无法可靠解析时，不得静默使用抓取时间补齐。该资讯保留在全部资讯，标记「发布时间缺失，无法核验时效」，不自动进入精选，除非现有业务规则另有明确、可验证的处理约定。

### 3.2 六维加权评分

| 评分维度    | 权重  | 含义                         |
| ------- | ---:| -------------------------- |
| 注塑直接相关性 | 25% | 文章是否明确涉及注塑工艺、注塑产线或直接相关应用   |
| 投资事件强度  | 20% | 事件是否包含可核实的投资、扩产、建厂、设备更新等信号 |
| 产品匹配度   | 20% | 资讯中产品/工艺与现有关注产品方向的适配程度     |
| 采购时效性   | 15% | 信息所反映需求的时间有效性，而非最近一次抓取时间   |
| 客户价值    | 10% | 事件主体或应用领域对目标行业的参考价值        |
| 信息完整度   | 10% | 是否有明确主体、事件、时间、地点、数据及可信来源   |

六维权重合计 100%。若各分项为 0–100 分，标准加权计算形式为：

```text
总分 = round(注塑直接相关性×0.25
          + 投资事件强度×0.20
          + 产品匹配度×0.20
          + 采购时效性×0.15
          + 客户价值×0.10
          + 信息完整度×0.10)
```

**实施约束：** Agent 必须先核对当前代码中的真实分数范围、计算公式和存储方式。若当前实现与「关于」页面公开规则不一致，应统一前后端口径并在交付说明中列明差异；不得悄悄发明第二套公式。历史数据不自动批量重算，除非确认存储字段、迁移方案和回滚方式。

### 3.3 分数阈值

「关于」页面已有的分数解释和 60 分阈值应保留。UI 需要明确显示阈值的业务含义，避免把分数表达为已确认采购事实。高分仅代表按照现有模型得出的较高综合价值/关注优先级，不代表已确认采购注塑机。

### 3.4 详情页七维 AI 分析

七个分析模块与六维评分分开呈现：

1. 资讯价值；
2. 商机价值；
3. 行动价值；
4. 产品匹配；
5. 竞争情况；
6. 伊之密优势；
7. 伊之密短板。

七维分析是文章解读，不是七个评分维度，也不自动触发任何销售流程。保留分析内容，但应区分原文事实、AI 推断和未确认事项；「行动价值」只展示分析建议，不新增任务系统、客户跟进按钮或 CRM 操作。

## 4. 信息架构与页面需求

保留现有导航体系，优先复用现有页面路径和组件。以下为功能要求，不要求改变 URL，除非当前路由存在缺陷。

### 4.1 首页

**页面目标：** 让用户快速找到最新资讯和高价值精选内容，并明确了解数据更新情况。

**页面结构：**

1. 网站名称/标识及全站搜索入口；
2. 一级导航：现有资讯、精选资讯/首页、热点榜、关于等功能入口按当前站点实际路由保留；
3. 简洁的资讯状态摘要；
4. 最新资讯与精选资讯视图或标签切换；
5. 主资讯列表；
6. 可选的分类入口和关联资讯入口。

**状态摘要字段：**

- 今日新增：按 `fetched_at` 统计今日成功新增的文章数；标签需明确为「今日新增/今日收录」，不可称为「今日发布」。
- 精选数量：定义明确的时间范围；若展示当日精选，按 `selected_at` 统计。
- 有效信源数：按信源状态统计可用信源数量。
- 最近成功采集时间：显示整个系统或逐信源最近一次成功时间，不得显示最近启动时间作为成功时间。

若现有数据不能可靠计算某项指标，显示「暂无数据」或隐藏该指标，不得写死演示数值。

**资讯列表卡片字段：**

- 新闻标题；
- 原始来源名称；
- 原始发布时间；
- 内容摘要（建议 2–3 行，超出截断）；
- 一级分类/主题标签；
- 现有六维总分或现有综合评分标识（如果文章已有评分）；
- 精选状态；
- 打开详情的明确入口。

**排序：** 默认「按新闻发布时间倒序」。至少提供「最新发布」和「综合评分优先」两种排序。排序要使用实际字段，不得按数组默认顺序或抓取时间替代发布日期。

**空状态：** 无最新内容时显示「暂无符合条件的资讯」，同时给出切换到全部资讯或调整筛选的入口。

### 4.2 全部资讯页

**页面目标：** 保留所有采集文章，支持搜索、筛选和理解未入选原因。

**搜索字段：** 标题、原始标题、摘要、来源名称、企业名称（若已有字段）、关键词/标签。搜索需忽略首尾空格，大小写按合理规则归一化。

**筛选条件：**

- 精选状态：全部 / 已精选 / 未入选；
- 新闻分类/主题标签；
- 信源；
- 发布时间范围；
- 注塑相关度等级（若系统有此字段）；
- 评分区间（仅对有分数的文章生效）；
- 未入选原因（未命中产品词、未命中工艺/事件词、超出时间窗、发布时间缺失、重复归并等）。

**排序条件：**

- 发布时间倒序；
- 抓取时间倒序；
- 综合评分倒序。

**列表显示：** 复用首页卡片样式，但需额外显示精选状态。未入选文章应显示具体原因，支持多个原因同时存在。不得只显示笼统的「低相关」。

**未入选原因枚举建议：**

- `OUTSIDE_TIME_WINDOW`：超出 360 天窗口；
- `PUBLISHED_AT_MISSING`：发布时间缺失/无法解析；
- `NO_PRODUCT_TERM`：未命中产品词；
- `NO_PROCESS_OR_EVENT_TERM`：未命中工艺词且未命中事件信号词；
- `DUPLICATE_EVENT`：疑似重复或已归并至同一事件；
- `MANUAL_REVIEW`：需要人工复核（如现有系统支持）。

如果存在多个失败条件，应展示全部命中原因，不能只展示第一个原因。

### 4.3 热点榜

**页面目标：** 展示指定短时间窗口内真正值得关注的新闻，而非按采集时间误判热点。

**时间规则：** 默认窗口为当前时间向前 48 小时。优先按原始新闻发布时间 `published_at` 过滤；不得使用 `fetched_at` 判断新闻是否属于近 48 小时。

**排序：** 按现有综合评分从高到低；分数相同则按 `published_at` 倒序。若当前热点榜使用其他已公开定义，需与「关于」页面的规则说明保持一致。

**空状态：** 窗口内没有符合条件的资讯时显示「近 48 小时暂无符合规则的热点」，并提供查看最新资讯的入口。不能把空结果解释为采集系统运行正常或失败，除非存在对应的系统状态数据。

**信息标识：** 明确显示「近 48 小时」及统计更新时间，避免用户误认为是历史累计榜单。

### 4.4 新闻详情页

**页面目标：** 让用户理解新闻事实、AI 分析和评分依据，并能访问原文。

**建议展示顺序：**

1. 新闻标题；
2. 来源、原始发布时间、抓取时间、最近 AI 分析时间；
3. 原文链接；
4. 事实摘要；
5. 关键事实/数据；
6. 六维评分、总分和计算依据；
7. 注塑工艺相关性说明；
8. 七维 AI 分析；
9. 命中关键词、分类/主题标签；
10. 关联资讯（P1）；
11. 原始来源信息。

**事实与推断边界：**

- 原文明确陈述的信息标记为「原文事实」或以事实摘要方式展示；
- AI 根据事实作出的解释标记为「AI 分析/推断」；
- 原文没有提供的数据、未确认的设备采购计划、未确认的制造工艺不得写成确定事实；
- 对于只涉及热成型、挤出等非注塑工艺的文章，应明确说明「与医疗制造相关，但未发现明确注塑工艺证据」等类似结论（仅当原文/模型判断有依据时展示）。

**评分呈现：**

- 展示六个维度的实际分项得分、权重和简短理由；
- 同时显示总分及当前阈值解释；
- 如部分维度无足够证据，不得伪造分值；应按现有规则处理缺失值，并显示「信息不足」或相应解释；
- 前端计算结果必须与后端/存储总分一致；
- 不应只用颜色表示高低，需配合文本标签/数字；
- 六维评分模块与七维分析模块分开展示。

**阅读体验：**

- 七维分析默认可折叠或按清晰的标题分块，避免页面过长；
- 原始标题与翻译标题有差异时分别展示；
- 长摘要适当折叠，但不能截断原文链接；
- 返回列表后尽量保留此前的筛选条件和滚动位置（技术可行时）。

### 4.5 关于页面

「关于」页面是业务规则的公开说明，必须与代码当前实际行为一致。建议改为分组折叠/目录锚点，至少包括：

1. 采集流程；
2. 当前信源及状态；
3. 硬筛选三项条件；
4. 六维评分及权重；
5. 60 分阈值的解释；
6. 七维 AI 分析说明；
7. 关键词分类；
8. 排除/未入选原因；
9. 更新时间字段解释；
10. 规则版本/最近更新时间。

页面显示的是实际运行规则，不能只写计划规则。信源状态应使用真实运行数据：正常、最近成功时间未知、暂不可用、未配置采集通道等；不要把「已配置」等同于「运行成功」。

### 4.6 信源状态（页面或关于页区域）

本期可以先在「关于」页面增加信源健康状态，不要求另建完整后台。每个信源至少展示：

- 信源名称；
- 采集通道/URL（如适合公开显示）；
- 是否启用；
- 最近尝试时间；
- 最近成功时间；
- 最近一次状态：成功 / 失败 / 部分成功 / 未配置；
- 最近失败摘要（若有）；
- 最近一次成功新增文章数（若现有数据可提供）。

如果当前采集程序没有记录这些字段，应在不破坏现有采集逻辑的前提下补充最小必要日志。不要只根据「最近执行时间」显示成功状态。

## 5. 视觉与交互规范

### 5.1 总体风格

- 定位为专业的 B2B 行业情报站，视觉克制、清晰、信息密度适中；
- 采用稳定的字号层级、统一间距和一致的卡片结构；
- 优先突出标题、来源、发布时间、分类、评分和摘要；
- 颜色仅用于状态/重点，不要给每个标签都使用高饱和色；
- 不使用大量无实际作用的装饰图表；
- 不引入销售漏斗、待办面板或 CRM 风格布局。

### 5.2 响应式要求

- 桌面端优先，建议内容主体宽度控制在适合阅读的范围；
- 平板端筛选区可收窄或折叠；
- 移动端筛选条件放入抽屉/折叠面板，卡片改为单列；
- 不出现横向溢出、按钮重叠、长 URL 撑破布局或评分表格无法阅读的情况；
- 点击区域清楚，链接与普通文本有区别。

### 5.3 日期、评分和状态视觉规则

- 绝对日期统一格式，建议 `YYYY-MM-DD`；时间可采用 `YYYY-MM-DD HH:mm`；
- 「X 天前」可作为辅助信息，不得替代原始日期；
- 所有相对时间须基于 `published_at`、`fetched_at` 等对应字段计算；
- 状态标签需同时使用文字，不得只依赖颜色；
- 缺失数据统一显示「未知」「暂无数据」或不展示，禁止虚构 0 分或虚构时间；
- 若分数为 0，应与「无分数/未分析」区分。

## 6. 数据字段与状态规则

Agent 需要映射现有数据模型；字段名可按现有技术栈调整，但语义必须满足以下定义。若已有同义字段，优先复用，避免重复存储。

| 逻辑字段                       | 类型/示例            | 说明                                                  |
| -------------------------- | ---------------- | --------------------------------------------------- |
| `id`                       | string/UUID      | 文章唯一标识                                              |
| `title`                    | string           | 站内显示标题                                              |
| `original_title`           | string/null      | 原文标题                                                |
| `source_name`              | string           | 原始来源名称                                              |
| `source_url`               | URL              | 原文链接                                                |
| `published_at`             | datetime/null    | 新闻原始发布时间，筛选/热点/最新排序的核心字段                            |
| `fetched_at`               | datetime         | 最近一次成功抓取时间；若需保留首次抓取时间则另设字段                          |
| `analyzed_at`              | datetime/null    | 最近一次 AI 分析完成时间                                      |
| `selected_at`              | datetime/null    | 进入精选的时间；非精选为 null                                   |
| `selection_status`         | enum             | selected / not_selected / pending / error 等，按现有实现映射 |
| `selection_reasons`        | array            | 未精选原因，可多选                                           |
| `summary`                  | text             | 事实摘要                                                |
| `category`                 | string/array     | 一级分类或主题分类                                           |
| `tags`                     | array            | 关键词/主题标签                                            |
| `matched_product_terms`    | array            | 命中的产品词                                              |
| `matched_process_terms`    | array            | 命中的工艺词                                              |
| `matched_event_terms`      | array            | 命中的事件信号词                                            |
| `score_relevance`          | number/null      | 注塑直接相关性得分                                           |
| `score_investment`         | number/null      | 投资事件强度得分                                            |
| `score_product_fit`        | number/null      | 产品匹配度得分                                             |
| `score_timeliness`         | number/null      | 采购时效性得分                                             |
| `score_customer_value`     | number/null      | 客户价值得分                                              |
| `score_completeness`       | number/null      | 信息完整度得分                                             |
| `total_score`              | number/null      | 现有总分                                                |
| `score_reasoning`          | object/text/null | 各分项评分理由；优先结构化存储                                     |
| `analysis_7d`              | object/null      | 详情页七维分析内容                                           |
| `injection_evidence_level` | enum/null        | explicit / indirect / none / unknown，P1 可逐步引入       |

以上为逻辑字段，不要求一次性增加所有数据库列。Agent 必须先核对已有字段、可用存储能力和 Coze 当前部署限制，再决定新增字段、JSON 字段或前端映射方式。

### 6.1 时间字段准则

- **新闻发布时间 (`published_at`)**：来自原始页面或可信元数据；是最新资讯排序、360 天硬筛选和近 48 小时热点的首选依据。
- **抓取时间 (`fetched_at`)**：仅说明系统何时获取文章；用于采集延迟与系统统计。
- **AI 分析时间 (`analyzed_at`)**：说明当前分析何时生成；文章重新分析后更新，不改变新闻发布时间。
- **进入精选时间 (`selected_at`)**：说明文章何时通过筛选/进入精选，不改变原始发布日期。
- 发布日期只有日期、没有时间时，应按站点统一时区转换规则处理；不能擅自填入任意时分秒并让其影响近 48 小时边界。建议保存原始时区/日期精度或使用明确的默认解析规则。
- 页面时区应统一配置；若项目已有时区则沿用。若没有配置，默认使用 `Asia/Shanghai`，并在文档/界面中保持一致。

### 6.2 评分缺失及一致性

- `null` 表示未评分或无法评分，不等于 0 分。
- 前端显示的分项、总分、阈值标签必须同源或使用同一公式。
- 无法从现有数据复原的历史分项不应伪造。可显示历史总分，并提示「未保存分项依据」；若按当前规则重新分析，必须记录新的 `analyzed_at`。

## 7. 资讯质量规则

### 7.1 工艺相关性标识（P1）

在原有硬筛选基础上增加一个辅助的工艺证据标签，不应在第一阶段偷偷改变既有入选结果：

- **明确注塑相关**：原文明确说明注塑机、注塑成型、注塑产线或对应工艺；
- **可能相关/待确认**：涉及医疗塑件、耗材或塑料加工，但没有明确制造工艺；
- **其他塑料成型工艺**：明确涉及热成型、挤出、吹塑等非注塑工艺；
- **未发现注塑证据**：原文没有足够信息支持注塑关联。

该标签优先用于解释和筛选，不立即改变硬筛选逻辑和历史分数。后续如需作为排除/降权依据，应先用历史样本评估误判，再调整规则和关于页面说明。

### 7.2 事实、推断及证据

- AI 摘要不能将推断性内容写成原文事实；
- 投资额、产能、设备采购计划、工厂所在地等关键事实必须在原文有依据；
- 原文仅提及企业扩张时，不得直接断言其将采购注塑机；
- 原文存在矛盾或来源信息不完整时，应提示不确定性；
- 建议为关键结论记录简短依据，至少指出依据来自标题、正文具体事实或关键词匹配；
- 任何引用或摘要都应能回到源 URL 核查。

### 7.3 去重与事件合并（P1）

- 先识别完全相同 URL、规范化 URL、标题高度相似或正文指纹相似的重复文章；
- 不得未经确认物理删除原始采集记录；
- 可在列表中聚合展示，并标明「同事件 N 个来源」；
- 事件主条目展示主要来源，详情页提供其他来源链接；
- 若只是同主题但事件不同，不应强行合并；
- 合并/归并应可撤回，且保留原始来源记录。

## 8. 功能优先级与开发任务

### P0：必须完成

1. 盘点现有实现并输出路由、数据字段、筛选/评分代码位置清单。

5. 全部资讯页显示精选状态和所有未入选原因。

7. 详情页将六维评分与七维分析分开，呈现总分与已有依据。
8. 缺失数据使用统一空状态，禁止演示数据混入生产展示。
9. 优化首页与详情页信息层级，确保桌面/移动端可用。
10. 关于页面与实际实现保持一致，清楚说明现有筛选、评分、分析和时间口径。

### P1：建议本次迭代随后完成

4. 分类趋势统计、热门工艺/材料/主题变化；

## 9. 错误处理与边界情况

| 场景       | 系统要求                                     |
| -------- | ---------------------------------------- |
| 原文没有发布时间 | 保留文章，标注发布时间缺失，不用抓取时间伪造发布日期               |
| 原文链接失效   | 文章仍可阅读已保存内容；原文入口提示链接不可访问（若已检测），不编造替代 URL |
| 采集任务失败   | 信源状态标记失败，记录错误摘要及最近成功时间；不要更新最近成功时间        |
| 正文解析失败   | 与 HTTP 抓取失败区分，保留已拿到的元信息并标记解析失败           |
| AI 分析失败  | 保留原始文章和摘要（如已存在），显示「分析暂不可用」；不要生成虚假的 0 分   |
| 同一新闻多来源  | 保留来源记录，可归并展示，不无声删除                       |
| 搜索无结果    | 显示空状态并提供清空筛选操作                           |
| 评分分项不完整  | 不计算/不伪造完整分数；按现有缺失值规则显示解释                 |
| 时间统计为 0  | 显示真实的 0；与「暂无数据/尚未采集」状态区分                 |
| 页面加载失败   | 有可理解的错误提示和重试入口，不显示空白页面                   |

## 10. 验收标准（可测试）

### 10.1 规则与数据

- [ ] 精选资格实现为 `时间 AND 产品词 AND (工艺词 OR 事件词)`。
- [ ] 时间筛选基于原始新闻发布时间，不基于抓取时间。
- [ ] 超过 360 天的文章不会通过现有硬筛选；文章仍保留在全部资讯。
- [ ] 未命中产品词的文章不会通过现有硬筛选；仍保留在全部资讯并显示原因。
- [ ] 未命中工艺词、同时也未命中事件词的文章不会通过现有硬筛选；仍保留并显示原因。
- [ ] 命中产品词、且命中工艺词或事件词、且在时间窗内的文章，在其他现有规则允许的情况下可进入后续评分流程。
- [ ] 发布时间缺失的文章不会使用抓取时间代替判断，并显示明确状态。
- [ ] 六维评分权重总和为 100%，前后端分数口径一致。
- [ ] 六维评分和七维分析被独立展示。
- [ ] 未经确认不批量重算历史总分。

### 10.2 页面

- [ ] 首页默认最新资讯按 `published_at` 倒序。
- [ ] 首页可切换/进入综合评分优先视图。
- [ ] 全部资讯支持按精选状态查看，并显示每篇未入选原因。
- [ ] 热点榜仅展示符合近 48 小时窗口的文章，使用 `published_at` 过滤。
- [ ] 热点榜空结果显示空状态与回到最新资讯入口。
- [ ] 新闻详情展示来源、原文链接、发布时间和抓取时间；可用时显示分析时间。
- [ ] 详情页六维分项、总分和七维分析内容没有互相混淆。
- [ ] 关于页规则说明与真实执行逻辑一致。
- [ ] 所有列表、筛选、空状态和详情页在桌面/移动端没有明显溢出、重叠或不可点击问题。

### 10.3 数据质量

- [ ] 抓取失败不会被记录成最近成功。
- [ ] 正文解析失败与抓取失败可以区分（如对应流程已接入）。
- [ ] AI 失败时不会伪造摘要、分数或评分理由。
- [ ] 同一事件多来源归并后，原始 URL 均可追溯。
- [ ] 所有展示统计均从真实数据计算；无法计算时使用明确空状态。

## 11. 测试样例建议

至少准备以下测试数据或手工验收案例：

1. 近 7 天、命中产品词和工艺词的文章：应通过硬筛选。
2. 近 7 天、命中产品词和事件词但未命中工艺词的文章：按现有 OR 规则可通过。
3. 近 7 天、命中工艺词但未命中产品词的文章：不得精选。
4. 超过 360 天、命中所有词的文章：不得精选，但保留在全部资讯。
5. 发布时间缺失、刚刚抓取的文章：不得把抓取时间当发布日期。
6. 明确只涉及热成型的医疗包装文章：可保留为行业资讯，显示非注塑工艺/注塑证据不足，不能自动断言有注塑设备采购计划。
7. 同一新闻的两个媒体转载：可归并，但两条来源都可追溯。
8. AI 分析失败但原文抓取成功的文章：仍可在全部资讯查看，并显示分析失败状态。
9. 分数为 0 与无分数文章：两者显示不同。
10. 近 48 小时内无符合条件的热点：热点榜显示正确空状态。
